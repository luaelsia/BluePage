# 사전 조사 결과 (구현 전 공식 문서 검토)

이 문서는 구현을 시작하기 전에 진행한 조사 결과를 정리한 것이다. 모든 결론은 Microsoft Learn / Microsoft Q&A / Microsoft Graph 공식 문서를 근거로 하며, 조사 시점은 2026년 7월이다.

## 1. Office Web이 로컬 파일을 직접 여는 공식 API가 존재하는가

**존재하지 않는다.** Office for the web(Office Online)은 브라우저에서 실행되는 웹 애플리케이션이며, 브라우저 보안 모델상 임의의 로컬 파일 시스템 경로에 접근할 수 없다. Microsoft 자신도 "로컬 파일은 OneDrive 등 온라인에서 접근 가능한 위치에 게시해야 한다"고 안내한다.

## 2. Word / Excel / PowerPoint Web 각각의 지원 범위

세 앱 모두 Microsoft Graph의 `driveItem.webUrl`을 통해 열리는 방식은 동일하다(모두 OneDrive/SharePoint의 driveItem이어야 함). 앱별 차이는 편집기 URL 패턴과 지원 기능(일부 고급 서식은 Web에서 제한)뿐이며, "로컬 파일 오픈 불가"라는 제약은 세 앱 모두 동일하다.

## 3. Office URI Scheme 지원 여부

`ms-word:`, `ms-excel:`, `ms-powerpoint:` URI 스킴이 존재하지만, 이는 **데스크톱 앱**을 여는 용도다(`ofe|u|<URL>` 형태로 데스크톱 Word/Excel/PowerPoint를 실행). Office Web과는 무관하며, 이 프로젝트는 데스크톱 앱을 사용하지 않기로 했으므로 채택하지 않는다.

## 4. Microsoft Graph API 활용 가능 여부

**가능하며, 공식적으로 지원된다.** `driveItem: createUploadSession`(대용량) 또는 `PUT /content`(4MB 미만)로 OneDrive에 업로드하면 응답에 `webUrl`이 포함되고, 이 URL을 브라우저로 열면 Office Web 편집기로 연결된다. 이번 구현의 핵심 메커니즘이다.

## 5. OneDrive 없이 가능한가

**불가능하다.** Microsoft가 만든 공식 "Office for the web PWA"(Edge에 설치되는 Word/Excel/PowerPoint 앱)조차 로컬 파일을 자동으로 열지 못하며, 사용자가 수동으로 OneDrive에 업로드해야 한다는 것을 실제 확인했다. 이는 Microsoft 자체 구현의 한계이지, 이 프로젝트가 만들어낸 제약이 아니다.

## 6. 임시 업로드 방식 가능 여부

가능하며, 이번 구현이 채택한 방식이다. OneDrive의 **App Folder**(`/me/drive/special/approot`)를 사용하면 `Files.ReadWrite.AppFolder`라는 최소 권한 스코프만으로 동작하고, 다른 OneDrive 콘텐츠에는 접근할 수 없어 안전하다.

## 7. 브라우저 자동 로그인 활용 가능 여부

브라우저의 저장된 로그인 세션에 직접 접근하는 것은 지원되지 않고 시도해서도 안 된다(브라우저 보안 경계 침해). 대신 **MSAL + WAM(Web Account Manager) 브로커**를 사용하면 Windows에 이미 로그인된 Microsoft 계정으로 사일런트 SSO가 가능하다 — 이것이 공식적으로 권장되는 "체감상 자동 로그인"이다.

## 8. Edge PWA 활용 가능 여부

Office Web을 PWA로 설치할 수 있지만, 로컬 파일을 자동으로 인식/업로드하지 않는다(직접 확인). 커맨드라인 플래그(`--localFileToOpen` 등)로 우회하려는 시도도 공식적으로 답변되지 않은 미지원 기능임을 확인했다.

## 9. WebView2 활용 가능 여부

WebView2로 `file://` 경로를 Office Web에 로드하려는 시도(`msOpenOfficeDocumentsInWebViewer` 플래그 등)는 파일을 그냥 다운로드시킬 뿐, Office Web에 로드하지 못한다(WebView2Feedback 이슈로 확인된 알려진 제약). 따라서 로컬 파일 우회 수단으로는 사용할 수 없다.

## 10. 공식 지원 방식 vs 비공식 우회 방법

| 구분 | 방법 | 평가 |
|---|---|---|
| 공식 | Microsoft Graph API 업로드 + webUrl | ✅ 채택 |
| 공식(제한적) | WOPI 프로토콜 자체 호스트 | 이론상 가능하나 Cloud Storage Partner Program 승인 필요 — 개인/사내 런처엔 비현실적 |
| 비공식/불가 | Office URI Scheme으로 Web 열기 | 애초에 데스크톱 앱 전용이라 해당 없음 |
| 비공식/불가 | WebView2 file:// 직접 로드 | Microsoft 측에서 지원하지 않음(다운로드로 대체됨) |
| 비공식/불가 | Edge PWA 커맨드라인 로컬파일 오픈 | 존재하지 않는 기능으로 확인됨 |

## 11. 결론

"로컬 파일 → Office Web"을 잇는 구간은 **OneDrive(App Folder) 업로드가 유일한 공식적이고 현실적인 방법**이다. 이 프로젝트는 이를 자동화하여 사용자가 업로드 과정을 의식하지 않도록 만드는 데 집중한다.
